engine, editor, language

Small enough to understand.
Opinionated enough to build with.

Sindri avoids parallel systems that drift apart. The editor edits the same world and scene representation the runtime uses. Decay crosses one typed host boundary. Native and browser hosts share the same engine concepts, assets, GPU abstraction, and renderer.

01

One scene model

2D and 3D entities, components, hierarchies and transforms live in versioned, canonical scene documents. Stable authored IDs stay separate from generation-checked runtime handles, and unknown component payloads are preserved by default.

02

A real editor

A searchable, collapsible hierarchy with drag-and-drop reparenting, generic component editing through the schema registry, sprite-sheet slicing and clips, undo/redo with drag merging, and Play mode on the real engine lifecycle.

03

Measured complexity

Systems are kept simple until profiling or real use proves they need to become more complicated. Features are exercised through real scenes, deterministic captures, and small games before they are described as capabilities.

decay

A gameplay language that refuses to guess.

Host members are typed: a misspelling such as this.transfrom.position.x is a compile error with a source location rather than a runtime surprise. @export fields are visible in the editor without running the script.

The language itself is engine-agnostic. It has safe entity, prefab and profile references, arrays and maps, bounded loops, typed host namespaces, and operation budgets — and still lacks structured vectors, coroutines, a debugger, and a full language server.

player.decay
script Player {
    @export
    let speed: f32 = 6.0;

    fn update(dt: f32) {
        let movement = Input.axis("ArrowLeft", "ArrowRight");
        this.transform.position.x += movement * speed * dt;

        if Input.just_pressed("Space") {
            print("Back to the middle");
            this.transform.position.x = 0.0;
        }
    }
}
